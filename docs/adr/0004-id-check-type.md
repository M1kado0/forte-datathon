# Седьмой тип: выдача наличных без предъявления документа, удостоверяющего личность

ADR 0003 вывел шесть типов из 22 размеченных нарушений. К ним добавляется седьмой: при выдаче наличных клиенту кассир обязан провести визуальную идентификацию по документу, удостоверяющему личность (п. 31 подп. 1) Правил № 231). Это видно сверху: либо документ появляется у стойки, либо нет. Тип добавлен по запросу команды 17.10.2026, пункт сверен с текстом adilet в тот же день (редакция постановления от 28.02.2022 № 19 с изменением от 10.11.2025 № 71).

## Considered options

- Оставить такие случаи запасному типу «Иное подозрительное действие». Отклонено: пункт точный, а описание без пункта стоит жюри балл за связь «норма → нарушение».
- Отдельный вид треков `document` против метки `document` внутри вида `object`. Выбран отдельный вид: иначе документ попадёт в тип 5 («посторонние предметы на рабочем месте») и один и тот же кадр даст два противоположных типа.
- Молчать, пока в видео нет ни одного трека документа (значит, детектор мог просто не уметь их искать). Отклонено: именно в нарушении документа в кадре и не будет, а пропуск нарушения дороже ложного срабатывания (ADR 0002). Вместо этого #32 обязан держать подсказку на документ всегда включённой, это записано в `contracts/data.py` (`TRACKS_SCHEMA`).

## Consequences

- Условия пункта проверяются до постановки типа (TZ-7.1): нужен клиент у стойки и наличные на столе, потому что п. 31 описывает выдачу наличных денег клиенту. Эпизод короче `min_payout_sec` (5 с по умолчанию) выдачей не считается.
- Описание говорит только о том, что видно: «документ, удостоверяющий личность, в кадре не виден». Подп. 1) допускает идентификацию через сервис цифровых документов, то есть по экрану телефона, а это по видео не проверяется, поэтому «идентификация не проведена» мы не утверждаем.
- Один визит — один вердикт: документ, увиденный в любой момент визита, снимает весь визит, потому что клиент предъявляет его один раз за операцию. Документ предыдущего клиента следующий визит не покрывает.
- Самый ложно-срабатывающий тип из семи: документ закрыт руками, лежит ниже стойки или предъявлен в телефоне — и тип сработает. Порог `min_payout_sec` и сам тип проверяются на LOVO в #34 первыми; если OWLv2 не находит документы на наших кадрах, тип выключается до события.
