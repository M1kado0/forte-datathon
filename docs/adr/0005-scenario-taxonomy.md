# Типы нарушений называем по сценариям из видео, а не по пунктам норм

Изменено 18.10.2026 в #73 по сверке с `src/rules/rules.yaml`: ключи на сейфе стали ближайшей нормой, потому что п. 80 отсылает к внутренним документам банка; сейф ссылается на п. 20, часть вторая; ближайшей нормой помечен весь тип «Посторонний предмет на столе кассира»; X-1 ссылается на Правила № 231 целиком, точного пункта о выдаче нет; «акт без пункта» заменено на «акт целиком»; в Consequences записано, что `workplace_left` и `count_without_controller` остаются до тикета эвристик.

ADR 0003 выводил типы из текста норм, и из 22 размеченных нарушений в них попали только 4. 18.10.2026 команда посмотрела все видео и описала сценарий каждого. Жюри сравнивает наш тип со скрытыми категориями, список которых не раскрыт (FAQ 8). Поэтому один сценарий из видео даёт один тип нарушения, название пишем словами сценария, а норма уходит в описание и ссылку. Заменяет ADR 0003. Тип по-прежнему дают эвристики, а не классификатор.

## Considered options

- Названия из норм, как в ADR 0003. Отклонено: «Доставка ценностей одним работником» не совпадёт ни с одной категорией, которую организаторы снимали.
- Один тип «сейф открыт или ключи на сейфе». Отклонено: команда описала это как два разных сценария, значит, скорее всего, это две скрытые категории.
- Когда эвристики молчат, ставить самый частый тип или несколько нарушений сразу. Отклонено: самая большая группа занимает 3 видео из 22, а каждый промах описывает предмет, которого детектор не видел, и это стоит баллов по критерию 4. Ставим запасной тип с нейтральным описанием, одно нарушение на видео.
- Эвристика ставит «нет нарушения». Отклонено до проверки на треках настоящих видео (#32): пропуск недопустим (FAQ 16), вердикт остаётся по ADR 0002.

## Consequences

- Тип ADR 0003 «Доставка ценностей одним работником» удалён: ни одна метка на него не ссылается, а п. 99 разрешает бригаду из двух человек. Типы «Рабочее место оставлено с незакрытыми ценностями» и «Пересчёт без контролирующего работника» остаются в `rules.yaml` до тикета эвристик под ADR 0005: на их id ссылаются эвристики и их тест. Тот тикет удаляет оба типа и переводит эвристику «деньги на столе, кассира нет» на тип «Наличные оставлены на столе вместо сейфа».
- При ближайшей норме описание называет один видимый факт: «дверца сейфа открыта», «удостоверение инкассатора в кадре не видно». Нарушение нормы не утверждаем. Для ноутбука п. 71 подп. 9) не цитируем: он требует 30 минут бездействия, а видео длится 16.5 с.
- Эвристики до заморозки получают типы, которые видны по классам COCO и трекам людей: ноутбук, посторонний предмет (`book` для X-24), посторонний человек, наличные при следующем клиенте, клиент ушёл. Ключи, открытый сейф и дверь получают эвристику, только если OWLv2 найдёт их на кадрах меток. X-13, X-44, X-17 и X-1 остаются записями в `rules.yaml` без эвристики и на новых видео получат запасной тип.
- В `data/labels.csv` X-47 склеивается обратно в X-4 второй строкой с 68 с (ADR 0002), X-30 получает тип «Посторонний в кассовом помещении».
