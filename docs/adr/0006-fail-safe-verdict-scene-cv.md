# Ветка A не может сказать «нарушения нет»; качество меряем по сценам, а не по видео

Статус: предложено 18.10.2026 в ветке `fix-the-cv-model`, после заморозки. Нужен ревью P1 и перезапуск сервиса у P2.

Организаторы снимали каждое нарушение вместе с чистым дублем той же сцены: те же люди, одежда и предметы на столе. Leave-one-video-out оставляет дубль отложенного ролика в обучении, и классификатор окон отвечает меткой дубля, а не тем, что видит. Поэтому recall 1.0 в `reports/metrics.json` получен по построению (ADR 0002), а порог 0.0045 не говорит, как модель поведёт себя на новом ролике. Группы сцен лежат в `data/scenes.csv` (`uv run python -m src.data.scenes`: медианный кадр каждого видео, остаток после общего фона, связные компоненты при корреляции ≥ 0.5; 9 сцен на 40 видео). Числа считает `uv run python -m src.models.scene_cv`, он пишет `reports/scene_cv.json` и строки в `experiments.csv`.

## Что измерено

Прокси-кэш: DINOv2-small, 448 px, 2 кадра в секунду, CPU. Это не эмбеддинги сервиса, P2 повторяет расчёт на родном кэше (`make all` теперь его включает).

- **Leave-one-video-out перевёрнут.** Видео AUC 0.29. Порог, при котором ловятся все 21 нарушение, помечает 18 из 19 чистых видео, как и в `reports/metrics.json`.
- **По сценам классификатор не лучше случайного.** Видео AUC 0.49. При recall 1.0 помечены все 19 чистых видео. Остальные варианты, проверенные по сценам (24 строки перебора 17.10: вычитание медианы видео, изменение за последние секунды, сетка 8×4, два способа взвешивания и сглаживания; и 2 варианта новизны областей кадра относительно чистых видео 18.10), дают AUC 0.40–0.61. Ни один не помечает меньше 17 чистых видео при recall 1.0.
- **Вложенная проверка по сценам пропускает нарушения.** Порог по остальным сценам, модель по остальным сценам, вердикт по отложенной: recall 0.90, пропущены X-20 и X-22, помечено 17 из 19 чистых.
- **На другом ракурсе оценки падают почти до нуля.** Виртуальная камера (зеркало, поворот 6°, наклон, зум 15%) на 7 видео: медиана оценки 0.995 на исходном виде и 0.000002 на новом. Из 3 видео с нарушением на новом виде не помечено ни одно. Выборка маленькая, и ракурс у жюри будет другим, но вывод один: вне обучающего вида оценка ветки A ничего не значит (FAQ 4).

## Решение

`FAIL_SAFE_VERDICT = True` в `src/models/analyze.py`: в `decide()` уходит порог 0, поэтому каждое видео, в котором есть хотя бы одно окно, получает вердикт `violation`. Ветка A, эвристики и kNN выбирают только тип и секунду. Видео, которые ветка A помечала и раньше, получают тот же ответ: тот же тип, ту же секунду. Обучение, `evaluate.py`, pickle и `FINGERPRINT` не меняются, на машине сервиса нужен `git pull` и перезапуск, переобучение не нужно. `False` возвращает сохранённый порог.

## Considered options

- **Порог по честной CV по сценам.** Отклонено: на новом ракурсе оценки ~1e-6 всё равно ниже любого порога, а вложенная проверка показывает пропуски и в знакомой обстановке.
- **Детектор «видео не похоже на обучение» включает вердикт.** Отклонено до 11:00: калибровать его не на чем, кроме 7 видео с виртуальной камерой, и X-20 с X-22 он бы не поймал.
- **Заменить ветку A новизной областей кадра.** Отклонено: AUC 0.48–0.53, вложенная проверка пропускает по два нарушения (X-24 и X-28 или X-44 и X-46).
- **Оставить как есть.** Отклонено: пропуск недопустим (FAQ 16), а по честной проверке он есть.

## Consequences

- Пропусков из-за ветки A больше нет. Цена: каждое чистое видео тоже помечено, обычно запасным типом «Иное подозрительное действие». В знакомой обстановке точность вердикта не меняется (вложенная проверка, прокси): было 19 из 21 нарушения и 2 из 19 чистых, стало 21 из 21 и 0 из 19, то есть 21 верный вердикт из 40 в обоих случаях.
- Поднять точность можно только новым сигналом, проверенным по сценам: эвристики по трекам людей и предметов, свои съёмки под другим углом (#43). До дедлайна это не успеть.
- Описание запасного типа больше не утверждает, что действие отличается от обычного: этого не видно, когда видео помечено только ради безопасности.
- Следующий шаг (после дедлайна): `group_of` в `src/models/windows.py` возвращает сцену из `data/scenes.csv`, и `train` выбирает голос, типы и kNN на честных фолдах.
